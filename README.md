# LyDSS

**L**u**y**i **D**ata**S**tore **S**truct —— 一组面向嵌入式与裸机环境的 C 容器实现。

十个容器各自编译成一个独立的静态库，**互不依赖**：用到哪个链哪个，不会因为想用一个栈而被迫带上哈希表。容器之间共用的底层操作放在一个内部头文件里，全部是 `static inline` 函数与宏，所以共用不产生链接依赖——十个开关可以任意组合，关掉任何一个都不会牵连其余。每个容器都能用 `inc/lydss_cfg.h` 里的宏单独裁剪掉，被关闭的容器不参与编译，产出的目标文件里没有任何函数。

## 设计取向

- **不替调用者做内存决策。** 存指针的容器（池、链表、表、桶）只管自己的节点，绝不释放调用者的业务对象；存值的容器（数组、动态数组、栈、队列、流、集合）一律拷贝，生命周期自洽。哪种语义写在每个容器的说明里，不留猜测空间。
- **定长优先。** 十个容器里有五个（池、数组、栈、队列、流）实现了静态构造，能把成员区绑定到调用者提供的内存上而不调用 `malloc`，是为没有堆、或不允许运行期分配的场景准备的。**但这些静态构造目前从库外还调不到**，原因见特征对比的脚注 8。
- **没有并发保护。** 没有任何容器加锁或做原子操作。跨中断、跨任务访问同一个容器需要调用者自己临界区保护。队列和流是环形缓冲，但**不是**无锁队列，不要当 SPSC 用。
- **断言而非静默容错。** 空句柄、非法参数由 `LYDSS_ASSERT` 拦下，默认会打印并陷入陷阱；下标越界、容器空/满这类**运行期正常状况**才返回 `false` / `NULL`。两者的边界是刻意划分的——**但表是例外**，它用返回值处理空句柄，见特征对比的脚注 12。

## 功能裁剪

`inc/lydss_cfg.h` 为每个容器提供一个开关，默认全开：

```c
#ifndef LYDSS_SET_ENABLED
#define LYDSS_SET_ENABLED 1
#endif
```

开关包在 `#ifndef` 里，所以在构建系统里 `-DLYDSS_SET_ENABLED=0` 即可覆盖，不必修改仓库文件。`LYDSS_ASSERT_ENABLED=0` 可以关掉全部断言，同时不再引入 `<stdio.h>`。

## 池（Pool）

**定位**：名字到对象指针的定长登记表，零额外分配。

启动阶段把少量全局对象登记进去，之后按名字取用。它不拷贝名字也不拷贝对象，只在自己的槽位数组里存两个指针，所以登记一个对象的成本就是一次线性扫描加两次赋值。

**适用**：驱动句柄注册、单例查找表、外设实例的命名索引——数量少（十几个量级）、启动后基本只读、名字是编译期字符串常量。

**不适用**：条目多或增删频繁的场景。查找是 `strcmp` 线性扫描，O(n)。

**注意**：`lypool_post` 返回 `void`，池满时**静默丢弃**，调用者无法感知失败。重名不检查——`post` 填第一个空槽，`get` 返回第一个匹配，`clear` 会清掉**所有**同名槽位。

## 数组（Array）

**定位**：给 C 原生数组补齐运行时元数据的定长存储原语。

它要解决的问题很具体：C 的数组一旦退化成指针就丢失了长度和成员大小，跨函数传递必须额外带上 `n` 和 `sizeof`。数组把这两个值放进句柄一起传。

它**刻意不跟踪"用了几个"**，因此没有 `push`/`pop`/`insert`/`remove`。全部 `length` 个槽位从创建起就存在、可读可写，索引边界对 `length` 判定。"已用多少"是上层容器的不变式，由栈的 `top`、队列的游标各自表达。

**适用**：定长缓冲区、查表数据、需要把长度随句柄传递的场合。`lyarray_get` 返回的成员地址在数组销毁前**始终有效**，所以也适合需要长期持有成员地址的场景（写入硬件寄存器镜像、交给 DMA）。

**不适用**：元素个数在运行期变化。它没有追加语义。

**注意**：`lyarray_create` 用 `calloc` 清零后交付，而 `lyarray_create_static` **不改动**调用者内存，槽位初值由调用者负责。

## 动态数组（Vector）

**定位**：自持成员区的动态数组。

`size`（已用数量）与 `capacity`（容量）分离是变长的前提：容量按 2 倍预支、已用数量逐个增长，使连续 n 次追加的搬移总代价为 O(n)，单次追加摊还 O(1)。空闲容量不初始化，索引边界对 `size` 判定，空闲槽位对外不可见。

它是**独立实现**的，不建立在数组之上——因为增长依赖 `realloc` 的原地扩张能力，而透过数组句柄拿不到。代价是增长逻辑重复一份。

**适用**：元素数量运行期才确定、以尾部追加为主的收集场景。`reserve` 可以一次预留避免中途重分配，`shrink` 可以在收集完成后把容量压回实际用量。

**不适用**：需要在中间插入；需要稳定的成员地址。

**注意**：任何触发重分配的操作（`push_rear`、`reserve`）之后，此前由 `lyvector_get` 取得的地址**全部失效**。`realloc` 失败时原缓冲区保持不变，句柄仍然可用。

## 栈（Stack）

**定位**：定长 LIFO，值拷贝。

**适用**：递归转迭代时的显式栈、括号/标签配对、撤销历史、状态机的状态回溯、表达式求值。深度可预估时用静态构造绑定一块静态数组，全程无堆分配。

**不适用**：需要访问非栈顶成员。只有 `push`/`pop`/`peek`。

## 队列（Queue）

**定位**：定长环形 FIFO，值拷贝。

`send`/`receive` 是**全有或全无**语义：要么整个成员进出成功返回 `true`，要么什么都不做返回 `false`。这和流的部分传输是刻意的区别。

**适用**：事件/命令队列、生产者消费者之间的定长缓冲、按固定结构体收发的消息传递。

**不适用**：字节流。队列的成员是定长的**类型化**成员，收发以"一个成员"为最小单位。要缓冲不定长字节用流。

**注意**：无并发保护，中断和主循环共用时必须自己加临界区。

## 链表（List）

**定位**：无界双向链表，只存 `void *data` 指针。

节点归容器所有，数据归调用者所有。这是唯一一个容量无上限的容器（受可用内存限制）。

**适用**：频繁在中间插入删除；已经持有节点句柄因而需要 O(1) 摘除；同一个业务对象要同时挂在多条链上。`lylist_insert_before`/`insert_after` 提供了其他容器都没有的定位插入能力。

**不适用**：按下标随机访问（要 O(n) 遍历）；对内存局部性敏感的热路径（节点分散分配）。

**注意**：`lylist_destroy` 释放节点但**不释放 `list` 句柄本身**，因为 `struct LyList` 是公开的、调用者可能栈分配它。堆上创建的链表句柄由调用者自己 `free`。`LYLIST_FOREACH` 在循环体内删除当前节点是未定义行为，宏会在循环体执行后读取 `node->next`。

## 流（Stream）

**定位**：定长环形字节传输通道。

成员单位是 `cell_t`（即 `unsigned char`），由库固定而非调用者指定。`in`/`out` 返回**实际传输的单元数**，可以少于请求量——这是流的签名特征，表达"通道当前只能吞下这么多"。

流和队列的结构与游标运算几乎一样，因为两者都建立在环形缓冲上（这在业界是常见的共享底座，参见 Linux 的 `kfifo`）。但两者处在不同抽象层级：队列是装类型化定长成员的**容器**，流是搬运无类型字节的**通道**。

**适用**：串口/传感器的收发缓冲、生产与消费速率不匹配的字节管道、协议帧的暂存与拼接。

**不适用**：按结构体收发。字节流里没有成员边界，边界得由调用者的协议层自己划。

## 表（Table）

**定位**：字符串键到值指针的哈希表，链式解决冲突。

**拷贝键、不拷贝值**：`lytable_set` 会为键分配副本，所以调用者传入的键可以是栈上的临时缓冲；但值只保留指针，`lytable_destroy` 不会释放它。

负载因子达到 0.75 时槽位数翻倍并迁移全部节点，所以插入是摊还 O(1)，查找平均 O(1)。哈希函数可以自定义，传 `NULL` 用内置的 FNV-1a。

**适用**：配置项存取、命令名到处理函数的分发、运行期动态建立的名字到对象映射、键的数量事先未知。

**不适用**：键不是字符串；需要有序遍历（无序，且扩容会改变顺序）。

**注意**：表在两处偏离了库内惯例。一是 `lytable_set` 返回 `int`（0 成功 / -1 内存不足），其余函数都用 `bool`/`NULL`；二是它**不用断言校验句柄**——`table` 或 `key` 为 `NULL` 时直接返回 `-1`/`NULL`，而另外九个容器遇到空句柄都会 `LYDSS_ASSERT` 中止。移植调试期要留意这个差异：表会静静地失败，别的容器会停在陷阱里。

## 集合（Set）

**定位**：元素唯一的哈希集合，泛型化程度最高。

调用者提供 `Hash_t` 和 `Equals_t` 两个回调，因此集合可以装任意类型的元素，而不只是字符串。元素以**值副本**存在节点里，元素大小在初始化时给定。

除了增删查，它提供 `lyset_relation` 判断两个集合的关系（不相交 / 有交集但互不包含 / 真子集 / 真超集 / 相等），这是其他容器都没有的成套集合语义。

**适用**：去重、成员判定（"这个 ID 见过吗"）、两组数据的集合关系比较。

**不适用**：需要保序或按下标访问。

**注意**：槽位数在初始化时固定，**不会 rehash**。元素数远超槽位数时会退化成若干条长链表，查找趋向 O(n)，所以初始化时就要按预估规模给足槽位。`lyset_add` 返回 `false` 有三种含义（已存在 / 元素为 `NULL` / 内存不足），调用者区分不出来。`lyset_relation` 是 O(n·m)，比较两个大集合会很慢。接口名是 `lyset_init` 而非 `lyset_create`，与其他容器的命名惯例不同。

## 桶（Bucket）

**定位**：带元数据的命名双向链表。

同时具备顺序（双向链表）、命名（按名字检索）和每项附带元数据三种能力，是库里语义最丰富的容器。名字和项都只存指针，**元数据是拷贝存储**（`LyBucketMetaType_COPY` 拷贝项本身，`ATTACH` 拷贝附属数据）。

写入分两类：`lybucket_put` 保证名字唯一（有同名则替换）；`lybucket_post`/`lybucket_insert` 不检查重名，但换来指定位置写入（头/尾、或某个定位名之前/之后）的能力。`patch_name`/`patch_item`/`patch_meta` 可以分别改三者其一。

**适用**：需要"有序 + 可命名 + 带附加信息"的登记表——插件/模块注册表、带优先级的处理链、每项要记住类型或尺寸的对象清单。

**不适用**：条目多的场景。检索是沿链表 `strcmp`，O(n)，没有哈希。

**注意**：`count` 字段是 `uint8_t`，**超过 255 项后 `lybucket_get` 会找不到条目**。`lybucket_remove` 返回一个已摘链但未释放的节点，而库里**没有**释放它的接口——需要"摘下但不销毁"时请改用 `lybucket_erase`（摘下并释放）。

### 列的含义

为避免歧义，每一列的判定标准如下。

- **连续内存**：成员本身是否存放在一块连续内存里。
- **有序性**：成员之间是否存在稳定且对外可见的先后关系。
- **可插入**：能否在已有成员**之间**的指定位置放入新成员（只能在端部追加不算）。
- **记名性**：成员是否以字符串名字标识。
- **关注成员大小**：容器是否需要知道单个成员占多少字节。
- **关注成员类型**：容器是否需要知道成员的 C 类型语义。
- **环形**：底层存储是否以环形缓冲实现，读写游标回绕复用空间。
- **复用性**：成员移除后其存储槽位能否被后续成员复用，无需重新分配。
- **关联性**：是否具备「键/名 → 值」的映射语义。
- **唯一性**：容器是否保证成员（或键）不重复。
- **支持静态创建**：能否把成员区绑定到调用者提供的内存上，不调用 `malloc`。
- **拷贝存储**：容器是否为成员建立副本（而非只保留调用者的指针）。
- **接受 NULL 值**：传入 `NULL` 成员是否为合法输入。
- **容量模型**：容量是固定、自动增长还是无上限。
- **查找 / 访问代价**：定位一个成员的渐进复杂度。
- **释放成员**：容器销毁时是否连带释放成员占用的内存。
- **成员地址**：取到的成员地址在后续操作后是否仍然有效。
- **需要回调**：是否要求调用者提供函数指针才能工作。
- **满 / 失败时的行为**：容量耗尽或分配失败时如何告知调用者。

### 脚注

1. 池的槽位数组（名字与对象指针）是连续的，但指针指向的对象本身分散在别处。
2. 表和集合的槽位数组连续（集合的槽位数组是柔性数组成员，与句柄同一次分配），挂在槽位上的冲突链节点分散分配。
3. 流的单元大小固定为 `cell_t`（即 `unsigned char`），由库决定，调用者不能指定。
4. 表拷贝键、只存值指针；桶存名字与项的指针、只拷贝元数据。
5. 链表的关联是节点之间的前驱后继拓扑关系，不是键到值的映射。
6. 集合本身不识别类型，但要求调用者用 `Hash_t`/`Equals_t` 回调注入类型语义，是十个容器里唯一对成员类型有间接依赖的。
7. `lypool_create_static` 有实现，但公开头文件里的声明被注释掉了，当前无法从库外调用。它还与其他静态构造行为不同：会把全部槽位清成 `NULL`，而 `lyarray_create_static` 刻意不改动调用者内存。
8. 静态构造函数已声明，但句柄类型在公开头文件里是**不完整类型**，库外写不出 `LyStack_t s;`（报 `storage size isn't known`），因此这些静态构造目前实际也调不到。解决它需要一个影响全部容器的设计决策（公开结构体 / 增加 `*_sizeof()` / 引入不透明存储类型），尚未决定。
9. 语法上合法且不会崩，但会与返回值歧义：池的 `get`、链表的 `pop`、表的 `get` 都用 `NULL` 表示「找不到 / 空」，存进 `NULL` 就无法区分两种情况。桶的 `put` 接受 `NULL` 项而 `patch_item` 断言非空，两者不一致。不建议依赖这个行为。
10. 桶的 `put` 保证名字唯一（同名替换），但 `post`/`insert` 不查重，可以造出同名条目。
11. `lypool_post` 返回 `void`，池满时什么都不做，调用者无法感知失败。这是十个容器里唯一无法报告失败的写入接口。
12. 表是唯一**不用断言**校验句柄的容器：`lytable_set`/`get`/`remove` 遇到 `table == NULL` 或 `key == NULL` 会返回 `-1`/`NULL`，而其余九个容器一律 `LYDSS_ASSERT`。它也是唯一用 `int`（0 / -1）而非 `bool` 表达成败的。
13. 集合显式检查 `elem == NULL` 并返回 `false`，是库里对 `NULL` 处理得最干净的一个——既不断言中止也不解引用崩溃。代价是 `lyset_add` 的 `false` 有三种含义（元素已存在 / 元素为 `NULL` / 内存不足），调用者无法区分。另外 `lyset_relation` 是 O(n·m)，两个大集合比较会很慢。
14. 静态构造出来的容器是例外：成员区是调用者提供的内存，`delete` 只解除绑定，不释放。解绑时存储描述会被清零，所以对已销毁的静态容器再查询长度或成员大小会得到 0（那本来就是未定义用法，不要依赖）。标 ✗ 的容器只管自己的节点，调用者的业务对象始终要自己负责。

「满 / 失败时的行为」一列说的是运行期。除此之外，五个连续存储的容器（数组、动态数组、栈、队列、流）在**创建时**还会拦截 `成员数量 × 成员大小` 的乘法溢出，溢出即返回 `NULL`，不会交付一个短于请求的缓冲区。

## 已知限制

- **静态构造目前从库外不可调用。** 见脚注 8。库内可用，对外需要一个尚未做出的设计决策。
- **没有任何并发保护。** 十个容器都不加锁、不做原子操作。
- **外部消费者无法 `#include <lydss_api.h>`。** CMake 没有声明公开的 include 目录，源文件靠相对路径 `"../inc/lydss_api.h"` 找到头文件。
- **`cell_t`、`Hash_t`、`Equals_t` 没有 `Ly` 前缀**，位于全局命名空间，`cell_t` 尤其容易与应用代码撞名。
- **没有位级容器。** 十个容器的最小操作单位都是字节或更大，最接近的流也是以 `cell_t`（即一个字节）为单位。位图、位域这类需求要新增容器，现有容器都做不到。
- 池、桶、表本质上是同一件事（名字到指针的映射）的三种实现，集合与表则是两个同构的链式哈希表。选型时留意重复。
- 部分容器存在已确认未修复的缺陷（桶超过 255 项后检索失效、`lypool_post` 无法报告失败、队列与栈未校验 `len == 0`、`LYLIST_FOREACH` 没有删除安全变体等）。这些在仓库的 `AGENTS.md` 里有逐条记录与行号。
